Keep what you read small. Read large files by range (Read with an offset and limit, or sed -n over a line range) rather than whole, and keep any one command's output under about 25,000 characters: a larger output is saved to a file and reading it back costs it twice. Do not page so finely that you need many more calls. Make independent calls together, but do not concatenate their outputs into one oversized response.

Reading in pieces must not mean reading less of the code. When the diff writes state that other code reads (a setting, a member, a global, a file or cache), grep for every reader and read each one, by range if it is large: a value the diff gives a new meaning or a wider range breaks readers that assume the old one, and that is a finding against the diff. When the diff reads shared state, find its writers and check what a concurrent or interrupted write leaves for the reader. Report as a gap only what cannot be checked here, never what was not read.
